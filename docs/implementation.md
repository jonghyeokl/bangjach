## 선택 이유와 한계

- 별도 플레이 이력 테이블 대신 리뷰 존재가 플레이 완료다. 재방문은 기존 리뷰 수정이며 리뷰 삭제 시 완료 기록도 제거된다.
- 원평점은 보존하고 통계의 normalized_rating만 사용자별 보정을 적용한다. lambda=10, 항목별 최소 표본 3명이다. 개인별 방문 테마 취향까지 일부 보정할 수 있는 초기 근사식이다.
- 전체 사용자 평균이 다른 테마에도 영향을 주므로 일별 작업은 전체 스냅샷을 재계산한다. PostgreSQL REPEATABLE READ와 작업 잠금으로 서로 다른 시점의 집계를 섞지 않는다. 초기 데이터 규모를 전제로 리뷰를 메모리에서 집계한다. 대규모 데이터는 SQL 집계로 옮길 수 있다.
- 팔로우 작업은 두 사용자 행을 UUID 순서로 잠근다. 공개 설정 변경도 해당 사용자 행을 잠가 요청 생성과 순서를 맞춘다.
- LLM 호출 동안 DB 트랜잭션을 열어 두지 않는다. 수정 시 updated_dt를 비교한 조건부 UPDATE로 오래된 결과가 최신 리뷰를 덮어쓰지 못하게 한다.
- OpenAI Responses API의 strict JSON Schema로 10개 주제별 boolean을 받는다. 전부 false도 정상 결과. 본문만 전송하며 store=false. 실제 호출 품질·비용은 API 키 설정 후 확인해야 한다.
- 공유 DB 기반 호출 제한을 추가했다. rate_limit 테이블은 해시 키와 시간 구간별 횟수만 저장한다. 외부 프록시의 전달 IP는 신뢰하지 않으며, 운영 네트워크 구성에 따라 IP 단위 제한이 여러 이용자를 묶을 수 있다.
- 앱의 iOS/Android 토큰은 SecureStore, 웹은 메모리만 사용한다. 웹 새로고침 후 다시 로그인한다. 앱에서 토큰 갱신은 한 번에 하나만 진행한다.
- 내 리뷰 조회의 선택 theme_id 필터는 테마 상세에서 기존 내 리뷰를 곧바로 수정하도록 연결하기 위해 추가했다.
- 휴대폰 소유 인증·비밀번호 재설정·시간표·예약·추천·연방 최적화·AI 사실 판정은 범위 밖이다. 리뷰 사진 업로드는 후속 요청으로 추가했다.

## 외부 설정이 필요한 항목

현재 로컬 SQLite만 사용한다. 남은 외부 설정은 OPENAI_API_KEY와 API 결제/크레딧 확인. 실기기 확인·스토어 출시는 별도다.

## 최종 로컬 검증 (2026-11-02)

- PostgreSQL 17: 테스트 10개 통과, Alembic 적용·check 일치. SQLite: 9개 통과, PG 전용 1개 제외.
- Ruff 검사·포맷, pip check 통과. 기능 API 32개 작업의 요청·응답 스키마를 Swagger에 제공한다.
- 앱 TypeScript·ESLint 통과, 웹·iOS·Android용 JS/Hermes 번들 생성 성공. 실기기 실행·네이티브 설치 빌드를 뜻하지 않는다.
- 모바일 폭 Chromium에서 가입 → 탐색 → 리뷰 → 캘린더 → 친구 요청/수락 → 공개 설정 → 리뷰 수정/삭제 통과.
- 브라우저 검증에서 설정 응답의 updated_dt를 PATCH에 다시 보내던 오류를 수정했다. 네비게이션은 기존 주 화면으로 돌아갈 때 중복 화면을 쌓지 않도록 변경했다.
- 앱에 React Native가 두 버전 설치되어 있던 의존성을 정리하고 SDK 54 버전 하나로 고정했다.
- 실제 LLM 공급자 호출, 운영 배포/마이그레이션/Scheduler 설정, iOS·Android 실기기 및 컨테이너 빌드는 미검증이다.


## 후속 변경: 하단 탭·친구 피드·리뷰 사진

- 하단 탭은 테마 검색 / 피드 / 마이페이지. 캘린더·친구·설정은 마이페이지에서 진입한다.
- 피드는 인증된 사용자의 수락된 친구 리뷰만 작성 시각 최신순으로 제공한다. 리뷰 수정 시 순서를 올리지 않는다.
- 사진은 임시 업로드 → 소유권 확인 → 리뷰와 함께 연결하는 방식이다. 리뷰 저장 실패 시 아직 공개되지 않는다. 삭제·분리 후에는 API 접근을 차단하고 24시간 뒤 정리 작업으로 저장소에서 제거한다.
- 새 `review_photo` 테이블에 소유자·리뷰·저장 경로·순서를 저장한다. 사진 바이트는 DB 대신 운영 Cloud Storage / 개발 로컬 폴더에 둔다.
- 사진 첨부·친구 피드·확대 보기까지 Chromium 통합 검증. 실제 휴대폰 사진 선택은 별도 확인이 필요하다. 운영 Cloud Storage 업로드는 후속 배포에서 검증했다.
- 배포·저장소 최초 설정 명령은 [배포 문서](deployment.md)에 정리했다.

후속 검증: PostgreSQL 13개 통과, SQLite 12개 통과/PG 전용 1개 제외. Alembic check 일치, Ruff·의존성 검사 통과.

운영 후속 적용: 사진 테이블·저장소·권한 설정 및 운영 업로드 확인, 매일 04:00(Asia/Seoul) 유지보수 예약 등록. 자세한 명령은 배포 문서 참고.

## 2026-11-05 변경

- 친구 → 방향성 팔로우. 기존 친구는 양방향 승인된 팔로우로, 요청은 해당 방향의 대기 상태로 이전.
- 기본 비공개. 승인된 팔로워에게 리뷰·캘린더·목록 공개. 리뷰 상세·사진·테마 리뷰 목록·키워드 개수도 같은 권한 적용. 공개 전환 시 대기 요청 승인. 익명 테마 집계는 전체 리뷰로 계산.
- OpenAI API: 인테리어~추천인원 7개 + 이머시브·분리·직원연출. 실제 유무가 아닌 언급 여부.
- 2단계 지역, 카페 67곳의 기존 주소 기반 세부 지역 보완. 테마 검색 is_played 표시.
- 다른 Codex 채팅에서 사용할 사용자 스킬 설치, 실제 DB의 테마 100개 통계 갱신 검증.
- SQLite·PostgreSQL 17 각각 테스트 31개, 앱 브라우저 통합 6개 통과. 계정·세션·테마·리뷰 보존 및 기존 관리자 인증 확인. OpenAI 실제 호출과 휴대폰 실행은 키 설정/실기기 확인이 남음.
